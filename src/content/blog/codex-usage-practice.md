最近非常青睐使用codex，一方面是比cc的订阅更加人性化；另一个更重要的方面是作为一个mac用户，codex给予了非常舒适的desktop体验

<br />

说一些我用的比较多的功能吧

首先是skill，虽然这个老生常谈了，但是codex确实go further了很多：能够有契约调用原生的computer use等功能，我觉得这个对于我来说很重要。我会每天定很多关于日报类型的skill，然后就牵扯到下一个内容，就是自动化，自动化使得这些skill能够在某个时间点自动触发，加上我写了一个本地的web（就像是我写这段md也是写了一个本地的web），可以天天很舒服的看到这些内容。除了这些内容之外，一些小feature，类似于在内置的浏览器中去做对应的前端批注修改，/goal这样的长时间工作，还是很美妙的

<br />

上面这部分可能有点偏题，其实作为一个programmer，让这个东西针对性变成工程上可用可能更加重要

对于我而言就是很暴力，但是暴力也是一种美学

首先我的分支策略完全不考虑有人跟我一起开发，如果你要一起开发，那你先看分支策略。然后我会把这份分支策略写入AGENTS.md中，让codex遵守。然后我会定义plan目录和doc目录，plan放置对应要做的feat，而doc放置实际的工程文档，细致到每一个文件

在这之后我会开始工作。在初期我会一个session用到死，我觉得没有任何必要切换session，初期的思路是很密集的，然后很多东西都是需要留在上下文中的，这些东西都很重要，没有说可以很好的方式总结的

直到项目平稳，我会开始对应使用worktree去工作，这个的前提当然就是之前的这些coding agent native的事情做的很好了，大家都知道plan中传达的哲学是什么样的，都知道doc里面的契约是什么样的，怎么管理分支怎么提pr，worktree就可以工作的很好，加上现在的codex对worktree的管理我感觉进步了很多，在我的这个场景下非常的轻松

接着就是codex github review，我觉得其实这个会很省心。我会固定构建一个review的skill，在每一个pr提出之后自动触发，然后创建10min的自动化，轮训结果，确认review的情况真实存在，确认不会越过边界修复，然后进行修复，修复后再次触发，直到没有问题。这一部分其实是必须要再次触发的，因为怎么说呢，我觉得gpt的rl一定很蠢，每次只返回三到四个问题，一定不会多返回的，所以如果一个重构的pr，影响面很大，那就有可能会有很多问题，但是gpt的奖励满足的情况下一定不会给你找全

其实查不多核心的就是这样，在这基础之上，可以做一些cicd去很流程的触发测试和发布或者部署，把这些部分也写入对应的AGENTS.md当中，codex也会做的很好

<br />

当然我觉得codex还有很多优化的点，我自己感觉到的就很多

首先是app的远程连接很难用，codex的线程的抽象一定之前做的很烂，导致远程控制的时候，你可以明显感觉手机和电脑不是在操作一个抽象层的东西，导致对应的手机上的bug多的可怕。我现在基本只会监督一下行为，不会觉得能够代替电脑工作

其次就是跟figma的集成不算好，跟pencil什么的就更烂了，我觉得这是model在这种原型管理上的rl缺失的问题，其实我觉得应该是好补齐这个问题的，就看数据了，不知道会不会有更多的设计师把这个部分用起来

然后就是前端能力，这个就不细说了，懂的都懂，这玩意就是越涂越丑
